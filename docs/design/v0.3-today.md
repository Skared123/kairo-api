# v0.3 Today: design

Scope from `docs/IDEA.md`: manual tasks and due follow-ups, in one screen that answers "what should I do today?".
Today replaces the home page. Later versions add to it: contact reminders (v0.4), study items (v0.5) and interview
prep (v0.6).

Built on decisions 033 (tasks), 034 (the Today screen) and 035 (whose "today").

## Data model

### `tasks`

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` | Primary key |
| `user_id` | `uuid` | FK to `users`, `ON DELETE CASCADE`, indexed. Every query filters by it |
| `job_id` | `uuid`, nullable | FK to `jobs`, `ON DELETE SET NULL`, indexed: deleting a job keeps its tasks (decision 033) |
| `title` | `text` | Required |
| `notes` | `text`, nullable | |
| `due_on` | `date`, nullable | A calendar day, no time zone, like `jobs.next_follow_up_on` |
| `done_at` | `timestamptz`, nullable | When it was marked done; null while open. Done tasks are kept (decision 033) |
| `created_at`, `updated_at` | `timestamptz` | |

A task's job must be one of the same user's jobs. The service checks it on every create and update.

## Endpoints

Every route is for a signed-in user (`@Can.Anyone()`) and works on that user's rows only: another user's task
answers 404, never 403.

| Route | Behavior |
|---|---|
| `GET /tasks` | The user's tasks. Filter: `jobId` (a job's tasks, for its detail page). Open first, by due day |
| `POST /tasks` | Creates a task. A `jobId` that is missing or another user's answers 400 `job_not_found`, the same answer for both, so nothing is revealed |
| `PATCH /tasks/:id` | Changes the title, notes, due day or job, or marks it done (`done: true` sets `doneAt`) or open again (`done: false`) |
| `DELETE /tasks/:id` | Deletes the task |
| `GET /today` | Everything Today needs in one answer: open tasks, tasks done in the last 48 hours, and the follow-ups of jobs in an open stage. Not filtered by day (decision 035) |

Each task in a response carries its job's `company` and `title` when it has one, so Today can show and link it
without another request.

The follow-up actions in Today use the v0.2 endpoint: **Done** sends `PATCH /jobs/:id` with `nextFollowUpOn: null`
and `nextFollowUpNote: null`; **Postpone** sends a new `nextFollowUpOn`.

Open stages are `to_review`, `to_apply`, `applied`, `interviewing` and `offer`. Jobs in `accepted`, `rejected` or
`discarded` never show up in Today (decision 034).

## Web screens

| Route | What |
|---|---|
| `/` | Today (decision 034): a quick add for tasks, then **Overdue**, **Today**, **Next 7 days** and **No date**, with **Done today** collapsed at the end |
| `/jobs/[id]` | Adds a **Tasks** section: the job's tasks, and adding one already linked to the job |

In each section, follow-ups and tasks are mixed and sorted by day:

- **A task:** a checkbox to mark it done (and undo it), its title, its job as a link, its day, and edit (a dialog)
  and delete.
- **A follow-up:** the job as a link, its note, **Done** and **Postpone** (pick a new day).

The browser decides which section each item goes in, with its own date (decision 035). Grouping is a pure function
(`lib/today.ts`) with unit tests. The header links to Today.

## Rules

- **Ownership in every query**, including the task's job: a task can never point to another user's job.
  `createTwoUsers()` tests prove it for every route.
- **The admin has no bypass**, as in v0.2.
- **Validation** with zod `strictObject` schemas; `dueOn` is a calendar day (`YYYY-MM-DD`).

## Tests

- API: end-to-end tests for every route, isolation with `createTwoUsers()` (also through `jobId`), keeping a job's
  tasks when it is deleted, and `GET /today` leaving out closed stages and old done tasks.
- Web: unit tests for the grouping, with a fixed "today"; Playwright for adding, completing, undoing, editing and
  deleting a task, the follow-up actions, the sections, and a job's tasks.

## Build order

Each step is one commit. API first, then the web app.

1. API: `Task` entity, migration, create, list, update (including done) and delete, with isolation tests.
2. API: `GET /today`.
3. Web: the Today page with its sections, read only, and the grouping with its unit tests.
4. Web: quick add, complete and undo, edit and delete tasks.
5. Web: the follow-up actions, Done and Postpone.
6. Web: a job's tasks on its detail page.
7. Web: end-to-end tests for the whole of Today.
