# v0.5 Learning: design

Scope from `docs/IDEA.md`: videos, courses, articles and side projects to work on, entered by hand, each with its
status and the skills it trains. Today shows one study item. In v0.6, the skills a posting asks for will become study
items, so skills are their own list from the start.

Built on decisions 040 (skills), 041 (status), 042 (the focus in Today) and 043 (no link to jobs).

## Data model

### `skills`

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` | Primary key |
| `user_id` | `uuid` | FK to `users`, `ON DELETE CASCADE`. Every query filters by it |
| `name` | `text` | As the user wrote it the first time, such as "TypeScript" |
| `key` | `text` | `name` trimmed and lowercased, set by the service. Unique per user: `(user_id, key)` |
| `created_at` | `timestamptz` | |

### `learning_items`

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` | Primary key |
| `user_id` | `uuid` | FK to `users`, `ON DELETE CASCADE`, indexed |
| `title` | `text` | Required |
| `kind` | enum `video`, `course`, `article`, `book`, `project`, `other` | Required |
| `url` | `text`, nullable | `http` or `https` |
| `status` | enum `to_start`, `in_progress`, `done`, `dropped`, default `to_start` | Decision 041 |
| `finished_at` | `timestamptz`, nullable | Set when it moves to `done`, cleared when it leaves it |
| `is_focus` | `boolean`, default false | At most one per user: a partial unique index on `(user_id) WHERE is_focus` (decision 042) |
| `notes` | `text`, nullable | |
| `created_at`, `updated_at` | `timestamptz` | |

### `learning_item_skills`

| Column | Type | Notes |
|---|---|---|
| `item_id` | `uuid` | FK to `learning_items`, `ON DELETE CASCADE` |
| `skill_id` | `uuid` | FK to `skills`, `ON DELETE CASCADE`, indexed |

Primary key `(item_id, skill_id)`. Both are always the same user's: the service only links skills it found or created
for that user.

## Endpoints

Every route is for a signed-in user (`@Can.Anyone()`) and works on that user's rows only: another user's item or
skill answers 404, never 403.

| Route | Behavior |
|---|---|
| `GET /learning` | The user's items: the focus first, then in progress, to start, done and dropped, latest change first. Filters: `status`, `skillId` |
| `POST /learning` | Creates an item. `skills` is a list of names: each is matched to the user's skills ignoring case, and created if new |
| `GET /learning/:id` | One item |
| `PATCH /learning/:id` | Changes any field. `skills` replaces the whole set. `status` sets or clears `finished_at`. `isFocus: true` moves the focus here in one transaction; `done` or `dropped` clears it |
| `DELETE /learning/:id` | Deletes the item and its skill links |
| `GET /skills` | The user's skills, by name, each with how many items train it |
| `PATCH /skills/:id` | Renames a skill. A name another of the user's skills already has answers 409 `skill_exists` |
| `DELETE /skills/:id` | Deletes the skill; its items stay, without it |
| `GET /today` | Adds `focus`: the focus item (id, title, kind, url, status, skills), or null |

Each item in a response carries its skills (`id`, `name`), by name.

## Web screens

| Route | What |
|---|---|
| `/learning` | A tab per status (and "all"), a filter by skill, and each item with its kind, skills, status (changed in place) and a star to make it the focus |
| `/learning/new` | The item form: title, kind, link, skills (type a name, pick a suggestion or create it), status, notes |
| `/learning/[id]/edit` | The item form, filled in, with delete |
| `/skills` | The user's skills with their item counts: rename, delete, and a link to the items of each |
| `/` | Today shows the focus under the date: its title (linking to its URL when it has one), kind and skills, and a link to Learning |

The header links to Learning. With six links it needs the mobile fix from the backlog; that stays a separate change.

## Rules

- **Ownership in every query**, including the skills an item links to. `createTwoUsers()` tests prove it for every
  route, `skills` names included: Grace's "TypeScript" is never Ada's.
- **The admin has no bypass**, as in v0.2.
- **Validation** with zod `strictObject` schemas; the URL is `http` or `https`; a skill name is 1 to 50 characters.
- **One focus per user**, enforced by the database, not only by the service.

## Tests

- API: end-to-end tests for every route, isolation with `createTwoUsers()`, skills matched ignoring case and never
  shared between users, the focus moving and cleared on done or dropped, `finished_at`, renaming into an existing
  name, and `GET /today` returning the focus.
- Web: unit tests for the item form; Playwright for adding, editing and deleting an item, skills (create, reuse,
  rename, delete), the status tabs and skill filter, the focus from the list, and the focus in Today.

## Build order

Each step is one commit. API first, then the web app.

1. API: `Skill`, `LearningItem` and their links, migration, create, list, read, update and delete with skills by name,
   with isolation tests.
2. API: status with `finished_at`, the focus, and the `status` and `skillId` filters.
3. API: the skills endpoints (list with counts, rename, delete).
4. API: the focus in `GET /today`.
5. Web: the learning list with status tabs and skill filter, and the create and edit forms.
6. Web: status and focus from the list, and the skills screen.
7. Web: the focus in Today.
8. Web: end-to-end tests for learning.
