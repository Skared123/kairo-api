# v0.1 Accounts: web app

The screens for v0.1 in `kairo-web`, on top of the API in `docs/design/v0.1-accounts.md`. Built on decisions 018 to
025.

## Screens

Every route starts with the locale, `/es` or `/en` (decision 023); `/` redirects to the preferred one.

| Route | Who | What |
|---|---|---|
| `/setup` | Anyone, only while `needsSetup` | First run: create the admin account |
| `/sign-in` | Guests | Email and password |
| `/` | Signed in | Home, a placeholder until Today (v0.3) |
| `/password` | Signed in | Change the password; the only screen while a change is required |
| `/admin/users` | Admins | List accounts, create one (shows the temporary password once), change role, deactivate, reset password |

## Rules

- **The API decides.** The web app hides what a user cannot do, but every check that matters happens in the API.
- **Session reads** happen in Server Components through one function, `getCurrentUser()`, which calls `GET /auth/me`
  with the session cookie and sits behind `<Suspense>` (Cache Components). `proxy.ts` only redirects guests early,
  from the cookie's presence.
- **A 403 with `password_change_required`** sends the user to `/password`.
- **Types** come from the API's OpenAPI document (decision 020); no hand-written API types.
- **Every string** is translated in Spanish and English (decision 023); forms use React Hook Form and zod (024).
- **A theme Switch** toggles light and dark, starting from the system's (decision 025).

## Build order

Each step is one commit in `kairo-web`:

1. Skeleton: `create-next-app`, `CLAUDE.md`, rewrites to the API, environment variables, web app manifest.
2. API client: generated types, `openapi-fetch` for the server and the browser, `getCurrentUser()`.
3. shadcn/ui, languages, theme, and the sign-in and first-run setup screens.
4. Signed-in layout, guest redirects and sign-out.
5. Change-password screen and the forced change.
6. Admin accounts screens.
7. Tests (Playwright and Vitest, decision 027) and README.
