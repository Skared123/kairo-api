# v0.1 Accounts: design

Scope from `docs/IDEA.md`: login and two roles. `admin` manages accounts, `user` uses the app. The first account
becomes admin; after that, only the admin creates accounts. The admin cannot see anyone's data.

Built on decisions 004 (TypeORM), 007 (zod), 008 (`@nestjs/authentication` in session mode) and 009 to 013.

## Data model

### `users`

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` | Primary key |
| `email` | `text`, unique | Stored lowercased, so `Ray@x.com` and `ray@x.com` are the same account |
| `name` | `text` | Shown in the UI |
| `password_hash` | `text` | Encoded scrypt hash from `PasswordHasher`; the password itself is never stored |
| `role` | enum `admin`, `user` | Defaults to `user` |
| `must_change_password` | `boolean` | True for accounts created by an admin (decision 011) |
| `deactivated_at` | `timestamptz`, nullable | Null means active; also records when the account was deactivated |
| `created_at`, `updated_at` | `timestamptz` | |

### Session tables

The tables `@nestjs/authentication` defines for the stores session mode needs, implemented with TypeORM and
verified with the package's store contract suite. Their `user_id` is text with no foreign key, so revoking sessions
on deactivation is explicit in code (`SessionService.revokeAll`).

## Endpoints

| Route | Access | Behavior |
|---|---|---|
| `GET /auth/setup` | Public | `{ needsSetup }`: whether the first admin still has to be created |
| `POST /auth/setup` | Public, only while there are no users | Creates the first admin and signs them in (decision 010) |
| `POST /auth/sign-in` | Public | Email and password. Wrong credentials and unknown emails both return 401 "Invalid email or password" |
| `POST /auth/sign-out` | Signed in | Ends the current session |
| `GET /auth/me` | Signed in | Current user: id, email, name, role, `mustChangePassword` |
| `POST /auth/password` | Signed in | Changes the password; requires the current one. Rotates the session and ends the account's other sessions |
| `GET /admin/users` | Admin | Accounts only: email, name, role, status, dates. Never any of their data |
| `POST /admin/users` | Admin | Creates an account and returns its generated temporary password, once (decision 017) |
| `PATCH /admin/users/:id` | Admin | Changes role or deactivates/reactivates. Deactivating revokes all of the account's sessions |
| `POST /admin/users/:id/password` | Admin | Replaces a forgotten password with a new temporary one, once, and ends the account's sessions |

## Rules

- **Deny by default.** Every route needs `@Public()`, `@Can(...)` or `@Can.Anyone()`; anything else is rejected.
- **At least one active admin.** An admin cannot demote or deactivate the last active admin, including themselves.
  Role and status changes take an advisory lock, so two concurrent changes cannot both pass the check (decision 017).
- **Forced password change.** While `must_change_password` is true, every route except `POST /auth/password`,
  `POST /auth/sign-out` and `GET /auth/me` returns 403 with `error: 'password_change_required'` (decision 016).
- **Deactivated accounts** cannot sign in, and the session provider returns `null` for them, which ends any session.
- **Passwords:** any non-empty password up to 128 characters, no composition rules (decision 015).
- **Requests** are validated with zod `strictObject` schemas through the global `StandardSchemaValidationPipe`.
- **CSRF and CORS:** `app.enableCsrfProtection()` and `session.trustedOrigins` with the web app's origin; CORS allows
  only that origin, with credentials. The origin comes from a new `WEB_ORIGIN` environment variable.
- **OpenAPI:** Swagger UI at `/docs` and the spec at `/docs/openapi.json`, which `kairo-web` uses for its types.

## Tests

- Unit tests for the rules that do not need a database (last-admin check, forced password change guard).
- End-to-end tests against the `kairo_test` database (decision 013): setup runs once, sign-in and sign-out, a
  deactivated account loses its session, a `user` gets 403 on every `/admin` route, the last admin cannot be demoted.
- A reusable two-user helper, `createTwoUsers()`, so every module from v0.2 on proves one user cannot read another
  user's rows.
- A route inventory: every route in the OpenAPI document answers a guest with 401, except an explicit list of public
  routes, so a route added later cannot be left open by mistake.

## Build order

Each step is one commit:

1. Snake case naming strategy, `User` entity and its migration.
2. zod validation pipe, Swagger, and the test database.
3. Authentication: TypeORM session store, setup, sign-in, sign-out, `/auth/me`.
4. Password change and the forced change on first sign-in.
5. Authorization and the admin endpoints, with deactivation.
6. End-to-end tests for permissions and user isolation.
7. README: how to run the project.
